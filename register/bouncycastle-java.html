Notes

  • ML-KEM, TLS 1.3: ML-KEM-only and hybrid ML-KEM/classical suites in the JSSE provider, aligned with IETF drafts; group names not in the claim.
  • ML-KEM, FIPS 140-3: FIPS-track library in early access; a separate bcpqc-fips artifact is described as non-certified.
  • ML-DSA, TLS 1.3: The JSSE provider added support for the draft-ietf-tls-mldsa specification in 1.82, described as enabling experimentation with ML-DSA in client-side authentication. Experimental on two counts: the IETF document is a draft, and the provider frames it as experimentation rather than a supported path.
  • ML-DSA, X.509: Hybrid certificates and post-quantum keys and signatures in X.509.
  • SLH-DSA, Primitive: Listed on the project’s specification page as a supported standardised algorithm.
  • Composite ML-DSA, X.509: Composite signature OIDs from 1.80 with a non-default JcaCompositeSignerInfoGeneratorBuilder.
  • LMS / HSS, FIPS 140-3: Inside BC-FJA (Bouncy Castle FIPS Java API), Legion of the Bouncy Castle Inc., FIPS 140-3 certificate 4943 issued 2025-01-17. Sunset 2027-01-16.
