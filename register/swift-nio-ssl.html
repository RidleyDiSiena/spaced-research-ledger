Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • BoringSSL – vendored, pinned at BoringSSL commit 817ab07ebb53da35afea409ab9328f578492832d. Inherits: FIPS 140-3. The package vendors BoringSSL as CNIOBoringSSL rather than linking it, and Package.swift records the exact commit. A BoringSSL release therefore does NOT reach swift-nio-ssl until the project re-vendors, which is why the pin is the load-bearing part of this record. The TLS surface is swift-nio-ssl’s own and is not inherited. [3] [4] [5]

FIPS 140-3

swift-nio-ssl holds no FIPS 140-3 certificate of its own. It takes its cryptography from BoringSSL (vendored, at BoringSSL commit 817ab07ebb53da35afea409ab9328f578492832d), and BoringSSL holds FIPS 140-3 certificates 5296, 5244, 5104, 4735, and has 3 modules in the CMVP queue. Whether a given algorithm is inside that validated boundary is BoringSSL’s answer, not this component’s: see the BoringSSL page. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you.

Notes

  • SecP256r1MLKEM768, TLS 1.3: The vendored BoringSSL (817ab07, release 2.37.5) defines no SecPMLKEM group, and the BoringSSL in PR 607 (merged 2026-10-09, main re-read 2026-10-15) has none either.
  • SecP384r1MLKEM1024, TLS 1.3: The vendored BoringSSL (817ab07, release 2.37.5) defines no SecPMLKEM group, and the BoringSSL in PR 607 (merged 2026-10-09, main re-read 2026-10-15) has none either.
  • MLKEM512, TLS 1.3: The vendored BoringSSL (817ab07, release 2.37.5) defines SSL_GROUP_SECP224R1/256R1/384R1/521R1, X25519, X25519_MLKEM768 and X25519_KYBER768_DRAFT00 only. Re-read on main after the 2026-10-09 re-vendor (BoringSSL 8eb25be6): still no MLKEM512 or MLKEM768 group; only MLKEM1024 was added.
  • MLKEM768, TLS 1.3: The vendored BoringSSL (817ab07, release 2.37.5) defines SSL_GROUP_SECP224R1/256R1/384R1/521R1, X25519, X25519_MLKEM768 and X25519_KYBER768_DRAFT00 only. Re-read on main after the 2026-10-09 re-vendor (BoringSSL 8eb25be6): still no MLKEM512 or MLKEM768 group; only MLKEM1024 was added.
  • MLKEM1024, TLS 1.3: The vendored BoringSSL (817ab07, release 2.37.5) defines SSL_GROUP_SECP224R1/256R1/384R1/521R1, X25519, X25519_MLKEM768 and X25519_KYBER768_DRAFT00 only; NIOTLSCurve stops at x25519_MLKEM768. Open PR 607 (2026-09-25) would vendor a BoringSSL with SSL_GROUP_MLKEM1024, reachable as NIOTLSCurve(rawValue: 0x0202); a vendoring refresh, not an ML-KEM plan, so not planned. UPDATE 2026-10-15: PR 607 MERGED on 2026-10-09; CNIOBoringSSL_ssl.h on main now defines SSL_GROUP_MLKEM1024 0x0202 (read 2026-10-15), while NIOTLSCurve on main still stops at x25519_MLKEM768 (raw 0x11EC). No release contains it yet (2.37.5 is still newest), so none stands for what a downstream can link today; the next release makes this cell available by raw value only, and whether that counts without a named NIOTLSCurve constant is for the user.
