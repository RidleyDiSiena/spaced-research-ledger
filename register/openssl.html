Notes

  • ML-KEM, FIPS 140-3: OpenSSL 3.5.4 FIPS Object Module submitted for FIPS 140-3 validation with ML-KEM, ML-DSA and SLH-DSA; certificate issuance NOT found on 2026-09-12 in two searches.
  • X25519MLKEM768, TLS 1.3: In the default supported-groups list with X25519 as the default keyshares.
  • SecP256r1MLKEM768, TLS 1.3: Shipped in 3.5.0; not in the default group list (only X25519MLKEM768 is).
  • SecP384r1MLKEM1024, TLS 1.3: Shipped in 3.5.0; not in the default group list. Larger key exchange messages, about 1700 bytes.
  • ML-DSA, Primitive: External-mu (ML-DSA-MU) digest support from 4.0.
  • ML-DSA, TLS 1.3: CHANGES 3.5.0: the TLS signature algorithm defaults include all three ML-DSA variants as first algorithms.
  • ML-DSA, X.509: Project PR 26575 (merged for 3.5): X.509 certificate generation with ML-DSA keys via the openssl command line (openssl req -x509 -newkey mldsa65). Chain-verification default standing not checked.
  • ML-DSA, FIPS 140-3: Same submission as the ML-KEM FIPS cell; certificate issuance not found on 2026-09-12.
  • SLH-DSA, TLS 1.3: Not offered natively for TLS in 3.5; oqs-provider bridged it on 3.2 to 3.4 and disables those combinations on 3.5 and later.
  • LMS / HSS, Primitive: Verification only, per SP 800-208, in both the FIPS and default providers.

Known Unknowns

Cells an engineer would ask about that no cited source has settled yet.

  • ml-kem / tls: bootstrap 2026-09-12, two passes: pure MLKEM512/768/1024 TLS group names are not in CHANGES.md 3.5.0 nor SSL_CTX_set1_curves.pod (only the three hybrids are); a secondary blog lists them, below the source bar
  • composite-ml-dsa / x509: bootstrap 2026-09-12, two passes: no composite ML-DSA in CHANGES.md 3.5.0, the 3.6 notes, or the openssl repo search
  • xmss / primitive: bootstrap 2026-09-12, two passes: XMSS absent from CHANGES.md 3.5.0 and the 3.6 notes (3.6 added LMS verification only); openssl issue 21360 is the open request
