Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • AWS-LC – linked. Inherits: TLS 1.3. The vendor’s builds ship AWS-LC as the cryptographic library, which is where the post-quantum curves come from – the article says so directly: “This works because both versions ship with AWS-LC as their cryptographic library, which includes support for post-quantum curves.” A distribution-built HAProxy links something else and inherits that library’s answer instead, which is why this edge describes the vendor build specifically. [4]

Notes

  • X25519MLKEM768, TLS 1.3: A BUILD-PROVENANCE ANSWER, not a version answer. PATROL 2026-10-15 ADDS A SECOND BUILD SHAPE AND LEAVES THE STATUS FOR A RULING: the vendor’s article is about AWS-LC builds, where the group must be configured (available); the source shows that a Community build against OpenSSL 3.5 with its QUIC API offers X25519MLKEM768 by default on QUIC listeners, and inherits OpenSSL’s default list (which has the hybrids from 3.5) on TCP listeners – which reads as default for that build. The vendor’s own sentence that the curves are ‘only available when HAProxy is built by us’ is about AWS-LC-era packaging and is contradicted for OpenSSL 3.5+ builds by HAProxy’s own code; whether the cell should say default with the build condition in since, or stay available on the vendor’s word, is for the user. The same HAProxy version compiled by a distribution against OpenSSL does not have these curves; the vendor’s builds ship AWS-LC and do. available rather than experimental because those packages are ordinary general releases rather than a preview or a flag – but anyone reading the version number alone will get this wrong, which is why the caveat is in the cell rather than only in the release notes. Automatic fallback to classical curves means enabling it does not break old clients.
  • SecP256r1MLKEM768, TLS 1.3: The NIST-curve hybrid matters for anyone whose policy prefers a P-256 half, which in practice means CNSA-aligned and federal deployments.

Known Unknowns

Cells an engineer would ask about that no cited source has settled yet. not checked means nobody has searched. searching means fewer than 2 passes are done. none found means the search was completed and came back empty, and the artifacts examined are named; a result older than 90 days is marked for recheck.

  • ml-dsa / tls – answered by its upstream: NOT OUTSTANDING WORK, and the work list was wrong to carry it as such. Serving an ML-DSA certificate is not something a terminator implements: it hands the certificate to the TLS library underneath, so the answer is that library’s and is already shown on this page as a derived cell, greyed and labelled with the upstream. The component has no independent answer to find. This is the third shape of gap that passes >= 2 would have mislabelled ‘none found’ – hence the inherited outcome, added the same day. Examined: the component’s own derives_from edge and the upstream’s ml-dsa/tls cell.
  • mlkem512 / tls – none found 2026-10-15: HAProxy documents no pure group: its blog (modified 2026-09-14) names X25519MLKEM768 and SecP256r1MLKEM768 for its own AWS-LC builds, and the 3.5 configuration manual (2026-10-01) passes curves to the library. Probably reachable by inheritance from AWS-LC, which has the pure groups – an inference, not a source. Patrol 2026-10-15, evidence moved but no release: 3.5-dev9 (2026-10-14) src/ssl_utils.c carries a registered-group table with “MLKEM512” (512), “MLKEM768” (513), “MLKEM1024” (514) mapped to NID_MLKEM* for AWS-LC and NID_ML_KEM_* for OpenSSL (commit c808988fa187, 2026-10-06), so curves MLKEM768 resolves by name on the development branch. Not in 3.4.7 (checked at the v3.4.7 tag). Still a gap: the names are a lookup table, a dev-only one, and no HAProxy document says a pure group negotiates. Examined: haproxy.com PQC blog (2026-07-01, modified 2026-09-14), HAProxy 3.5 configuration manual (2026-10-01), haproxy/haproxy src/ssl_utils.c on master (3.5-dev9) and at v3.4.7.
