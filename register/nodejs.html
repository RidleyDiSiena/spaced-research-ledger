Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • OpenSSL – linked, pinned at OpenSSL 3.5 (24.x line). Inherits: Primitive, TLS 1.3, X.509, FIPS 140-3. Node.js statically links OpenSSL and exposes it through node:crypto. The project’s own 24.7.0 release post attributes the post-quantum algorithms to OpenSSL 3.5 on the 24.x line, so what Node offers advances only when Node rebuilds against a newer OpenSSL. [4]

FIPS 140-3

Node.js holds no FIPS 140-3 certificate of its own. It takes its cryptography from OpenSSL (linked, at OpenSSL 3.5 (24.x line)), and OpenSSL holds FIPS 140-3 certificate 4985, and has a module in the CMVP queue. Whether a given algorithm is inside that validated boundary is OpenSSL’s answer, not this component’s: see the OpenSSL page. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you.

Notes

  • ML-KEM, Primitive: New crypto.encapsulate() and crypto.decapsulate() methods, plus ML-KEM in WebCrypto.
  • X25519MLKEM768, TLS 1.3: Inherited from the statically linked OpenSSL 3.5 default group list.
  • MLKEM512, TLS 1.3: Inherited from the bundled OpenSSL 3.5 (v26.x 3.5.9; v24.x and v22.x 3.5.9 from 24.22.1 / 22.23.4 on 2026-10-21, 3.5.8 before): lib/tls.js DEFAULT_ECDH_CURVE = ‘auto’ gives OpenSSL’s default list, which names hybrids only; the pure groups are selectable through ecdhCurve. Node itself documents no pure group.

Node itself documents no pure group.
  • MLKEM1024, TLS 1.3: Inherited from the bundled OpenSSL 3.5 (v26.x 3.5.9; v24.x and v22.x 3.5.9 from 24.22.1 / 22.23.4 on 2026-10-21, 3.5.8 before): lib/tls.js DEFAULT_ECDH_CURVE = ‘auto’ gives OpenSSL’s default list, which names hybrids only; the pure groups are selectable through ecdhCurve.
