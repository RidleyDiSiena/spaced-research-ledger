Notes

  • ML-KEM, TLS 1.3: Hybrid ECDH+ML-KEM and pure ML-KEM key exchange; used across AWS service endpoints. Hybrid suites supported only on Linux per AWS KMS documentation (d0001:21).
  • X25519MLKEM768, TLS 1.3: Named in the security policy tables as x25519+mlkem768, alongside secp256r1+mlkem768, secp384r1+mlkem1024 and pure mlkem1024. Reached by choosing a policy, not by default: the documentation says a policy supporting post-quantum must be configured. s2n-tls must be built against AWS-LC for any of it.
  • SecP256r1MLKEM768, TLS 1.3: In the same policy tables as the X25519 hybrid.
  • SecP384r1MLKEM1024, TLS 1.3: In the same policy tables; the CNSA 2.0 pairing.
  • ML-DSA, TLS 1.3: ML-DSA certificates for TLS 1.3 authentication in the default_pq and cnsa_2 policies. Those are named policies, not the library default, so ‘available’.
  • ML-DSA, X.509: An ML-DSA certificate is configured exactly as an RSA or ECDSA one would be.
