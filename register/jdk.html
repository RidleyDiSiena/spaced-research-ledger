Notes

  • ML-KEM, Primitive: JEP 496: native JCA engine classes, ML-KEM-512/768/1024.
  • ML-KEM, X.509: keytool generates ML-KEM key pairs and certificates; the certificate must be signed with a signature algorithm.
  • ML-KEM, FIPS 140-3: Not in any module of this project: the CMVP validated list and the Modules In Process list were scanned on 2026-09-12 and name none carrying it.
  • X25519MLKEM768, TLS 1.3: JEP 527 delivers hybrid TLS 1.3 key exchange in JDK 27, and the Curve25519 optimisation claim names X25519MLKEM768 as a group whose key generation it speeds up. Neither claim states the default group list, so ‘available’, not ‘default’.
  • ML-DSA, Primitive: JEP 497; JAR signing with ML-DSA from JDK 26.
  • ML-DSA, X.509: JEP 497, delivered in JDK 24: keytool generates ML-DSA key pairs and certificates, and KeyFactory converts an ML-DSA public key to and from its X.509 encoding. The same JEP explicitly rules JAR-file signing OUT of scope for want of a standard, so certificate handling and JAR signing arrived separately – JDK 26 added the JAR signing, per the ledger. The distinction is worth keeping: a component can mint a certificate long before every consumer of one accepts it.
  • ML-DSA, FIPS 140-3: Not in any module of this project: the CMVP validated list and the Modules In Process list were scanned on 2026-09-12 and name none carrying it.
  • SLH-DSA, FIPS 140-3: Not in any module of this project: the CMVP validated list and the Modules In Process list were scanned on 2026-09-12 and name none carrying it.
  • LMS / HSS, FIPS 140-3: Not in any module of this project: the CMVP validated list and the Modules In Process list were scanned on 2026-09-12 and name none carrying it.
  • XMSS / XMSS^MT, FIPS 140-3: Not in any module of this project: the CMVP validated list and the Modules In Process list were scanned on 2026-09-12 and name none carrying it.
