Notes

  • ML-KEM, Primitive: Available rather than default: CNG exposes ML-KEM to a caller that asks for it, and nothing in the announcement says any existing Windows API silently starts using it. A CONFLICT worth knowing about, recorded rather than resolved: the CNG API reference pages on Microsoft Learn still carry the banner “available in pre-release versions of the Windows Insider Preview”, while the dated GA announcement says generally available in shipped builds. The announcement is the later and more specific statement, so this cell follows it; if the reference pages are right, this is experimental instead.
  • ML-DSA, Primitive: All three parameter sets are selectable: the example sets BCRYPT_MLDSA_PARAMETER_SET_44, and 65 and 87 are named alongside it.
  • SLH-DSA, Primitive: A PRECISE AND UNUSUAL NEGATIVE, from the enumeration that settles it: CNG’s algorithm identifier list DEFINES BCRYPT_SLHDSA_ALGORITHM (L”SLH-DSA”, FIPS 205) and says of it “This algorithm is not currently implemented by the default CNG provider.” So the name exists and the default provider does not answer to it. That is deliberate rather than an oversight – CNG is a provider architecture, and defining the identifier is what lets a hardware key storage provider expose the algorithm under a name Windows software already knows. Which is exactly the join between this register’s platform and hardware categories: the identifier Windows publishes is the one an HSM’s KSP would implement. none is the right status because this column asks what the component itself does; it is NOT evidence that the algorithm is unreachable on Windows. Note also that Microsoft’s own SymCrypt – the library under CNG – does implement LMS, XMSS and ML-DSA per its changelog, so the gap here is the provider surface rather than the mathematics.
  • Composite ML-DSA, Primitive: The paired half of the composite-ml-dsa/x509 cell on windows-capi2: the same July 2026 update shipped composite into both the primitive API and the certificate layer, and Microsoft describes them as one delivery. The prerelease banner on the identifier page is the SAME conflict this file already records on its ML-KEM cell, one release later and now with a checkable cause – the page’s last edit predates the GA. available, not default: a caller has to name the algorithm. Microsoft’s composite is specifically ECDSA+ML-DSA (“to combine the traditional digital signature algorithm ECDSA with ML-DSA”), not the full set of pairings the draft registers.
  • LMS / HSS, Primitive: A PRECISE AND UNUSUAL NEGATIVE, from the enumeration that settles it: CNG’s algorithm identifier list DEFINES BCRYPT_LMS_ALGORITHM (L”LMS”, RFC 8554) and says of it “This algorithm is not currently implemented by the default CNG provider.” So the name exists and the default provider does not answer to it. Known Unknowns

Cells an engineer would ask about that no cited source has settled yet. not checked means nobody has searched. searching means fewer than 2 passes are done. none found means the search was completed and came back empty, and the artifacts examined are named; a result older than 90 days is marked for recheck.

  • ml-kem / fips – searching, 1 of 2 passes: Not in any validated module today, and not callable absent either. The 2026-09-13 CMVP scan read every Microsoft module of this family: Cryptographic Primitives Library (certificate 5410, 88 approved algorithms), its kernel-mode twin (5408, 84) and SymCrypt (5313, 55), and not one names a post-quantum algorithm. But a Kernel Mode Cryptographic Primitives Library submission has been at FINALIZATION – the last phase before a certificate – since 2026-08-17, and the Modules In Process list never publishes what is in a submission. So none would be wrong by the time it was published. This is the gap the register’s own rule produces: a pending submission blocks every absence. Second pass: the certificate, when it issues, or a Microsoft statement about the submission’s contents. Examined: CMVP validated module search, vendor Microsoft, certificate pages 5410, 5408 and 5313 (approved-algorithm lists), CMVP Modules In Process list.
  • ml-dsa / fips – searching, 1 of 2 passes: As ML-KEM: absent from every issued Microsoft certificate read, and blocked from being called absent by the same submission at Finalization. The two move together in Microsoft’s announcements, so they will likely be answered by the same certificate. Examined: certificate pages 5410, 5408 and 5313 (approved-algorithm lists), CMVP Modules In Process list.
