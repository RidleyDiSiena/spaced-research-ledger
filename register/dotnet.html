Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • OpenSSL – platform. Inherits: Primitive, X.509, FIPS 140-3. On Linux .NET’s cryptography is the operating system’s. Microsoft’s own cross-platform cryptography document states that .NET apps have access to FIPS-validated algorithms if the OS libraries are FIPS-validated, and that Linux requires OpenSSL 3. This entry is the LINUX half; the Windows half is the CNG edge below, and macOS is neither – the same document records that OpenSSL support on macOS was removed, and .NET’s post-quantum APIs need CNG or an OpenSSL that has the algorithms, so macOS has no recorded post-quantum path at all. [6]
  • Windows CNG – platform. Inherits: Primitive, X.509, FIPS 140-3. The Windows half of the same document: .NET’s cryptography on Windows is CNG’s, and its post-quantum APIs require a Windows whose CNG has the algorithms. PROMOTED from an external edge the same day the platform pass made Windows CNG a component – which is what the promotion invariant in the validator exists to force, and it did: the check fired on this edge before anyone remembered it was here. [7]

FIPS 140-3

.NET holds no FIPS 140-3 certificate of its own, and there is no single answer for it: which of its 2 backends this build carries decides, and that is a build-time choice no register can see. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you. What each backend holds:

  • OpenSSL (platform) holds FIPS 140-3 certificate 4985, and has a module in the CMVP queue. See OpenSSL.
  • Windows CNG (platform) holds FIPS 140-3 certificate 5313. See Windows CNG.

Notes

  • ML-KEM, Primitive: Requires Windows with CNG PQC support or an OpenSSL with the algorithms.
  • ML-DSA, Primitive: MLDsa members renamed SecretKey* to PrivateKey* in .NET 10, a breaking change. Corrected by the 2026-09-12 bootstrap: the ledger’s claim read the SYSLIB5006 gate as covering only the PEM helpers. Microsoft’s own page says the class itself is gated – “The MLDsa, SlhDsa, and CompositeMLDsa classes are marked as [Experimental] under diagnostic SYSLIB5006 until development is complete” – so this is experimental, not available. MLKem is NOT so marked, though some of its methods are. The same gate was confirmed still present in .NET 11 RC 2 (2026-10-13); the SlhDsa and CompositeMLDsa cells below share this evidence.
  • ML-DSA, X.509: CertificateRequest gained (X500DistinguishedName, MLDsa) and (String, MLDsa) overloads in net-10.0, each carrying [Experimental(“SYSLIB5006”)], so a certificate or CSR can be built on an ML-DSA key behind that gate.
  • SLH-DSA, Primitive: Corrected by the 2026-09-12 bootstrap: the ledger’s claim read the SYSLIB5006 gate as covering only the PEM helpers. Microsoft’s own page says the class itself is gated – “The MLDsa, SlhDsa, and CompositeMLDsa classes are marked as [Experimental] under diagnostic SYSLIB5006 until development is complete” – so this is experimental, not available. MLKem is NOT so marked, though some of its methods are.
  • SLH-DSA, X.509: CertificateRequest (X500DistinguishedName, SlhDsa) and (String, SlhDsa) overloads in net-10.0, same SYSLIB5006 gate.
  • Composite ML-DSA, Primitive: Composite ML-DSA in System.Security.Cryptography; PEM import/export helpers still experimental behind SYSLIB5006 (d0001:20). Corrected by the 2026-09-12 bootstrap: the ledger’s claim read the SYSLIB5006 gate as covering only the PEM helpers. Microsoft’s own page says the class itself is gated – “The MLDsa, SlhDsa, and CompositeMLDsa classes are marked as [Experimental] under diagnostic SYSLIB5006 until development is complete” – so this is experimental, not available. MLKem is NOT so marked, though some of its methods are. Patrol 2026-10-15: .NET 11 RC 2 (2026-10-13) adds a sibling, CompositeMLKem (post-quantum plus classical KEM, same SYSLIB5006 gate, on platforms that already have ML-KEM). Composite ML-KEM is not a register row – one component carrying it is not two, which is the bar – so it is recorded here and in releases only.
  • Composite ML-DSA, X.509: CertificateRequest (X500DistinguishedName, CompositeMLDsa) and (String, CompositeMLDsa) overloads in net-10.0, same SYSLIB5006 gate. .NET is the only component in the register with composite certificates at all.
