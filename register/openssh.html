Notes

  • ML-KEM, SSH: Recorded on the ML-KEM row rather than a hybrid-group row, which is what the vocabulary’s meaningful grid says to do and why: SSH names its own hybrid methods (mlkem768x25519-sha256) instead of borrowing the IANA TLS group names the hybrid-kex rows hold. OpenSSH also ships sntrup761x25519-sha512, a hybrid over NTRU Prime, which has no row here – one component carrying an algorithm is not two, which is the bar for adding one. Worth stating plainly because it is rare: this is post-quantum key agreement that happens whether or not the operator has heard of it.
  • Composite ML-DSA, SSH: Patrol 2026-10-15: default (was experimental, 10.4). The scale’s own words for a signature are ‘accepted by default in verification paths’, and at the 10.6 tag ssh-mldsa44-ed25519 is in the default accepted list for host keys and user keys, and sshd loads an mldsa44-ed25519 host key by default if one exists. What is NOT default: ssh-keygen -t still defaults to ed25519 for user keys, and the algorithm sits last in the preference list, so an ed25519 host key wins where both exist. Also note the name change – the 10.4 experimental type ssh-mldsa44-ed25519@openssh.com and the 10.6 type ssh-mldsa44-ed25519 are different wire names; keys from 10.4 do not carry over. The algorithm row is composite-ml-dsa (ML-DSA-44 paired with Ed25519, draft-miller-sshm-mldsa44-ed25519-composite-sigs), the only post-quantum signature any SSH component in the register ships. History: 10.4 (2026-07-06) ‘add experimental support for a composite post-quantum signature scheme that combines ML-DSA 44 and Ed25519 … This scheme is not enabled by default’; recording it then required flipping the grid’s ssh/composite pair to yes.
  • XMSS / XMSS^MT, SSH: A CELL THIS REGISTER ALMOST COULD NOT HOLD. Until 2026-09-13 the meaningful grid called stateful hash-based signatures over SSH not-a-question, on the reasoning that SSH registers no such key type – and OpenSSH had carried ssh-xmss@openssh.com for years before removing it here. The validator refuses a cell in a pair marked meaningless, so the grid was corrected first and this cell written second. The status is none rather than a gap because the project states the removal outright; and note what it is NOT evidence of – OpenSSH says in the same breath that it expects to implement a post-quantum signature scheme, so this is a retreat from one approach rather than from the problem.

Known Unknowns

Cells an engineer would ask about that no cited source has settled yet. not checked means nobody has searched. searching means fewer than 2 passes are done. none found means the search was completed and came back empty, and the artifacts examined are named; a result older than 90 days is marked for recheck.

  • ml-dsa / ssh – none found 2026-10-15: Searched twice and found no implementation, and the second pass found the reason: THERE IS NO SETTLED STANDARD TO IMPLEMENT. ML-DSA for SSH sits in competing INDIVIDUAL drafts – draft-rpe-ssh-mldsa-03 (16 April 2026, standards track, names mldsa-44/65/87 and says implementations SHOULD do mldsa-65) and draft-sfluhrer-ssh-mldsa-06 – with neither adopted by the sshm working group, while the hybrid KEY EXCHANGE half went the other way and is an adopted working-group document (draft-ietf-sshm-mlkem-hybrid-kex-10). That asymmetry is the finding: SSH’s post-quantum key agreement is standardised and shipping by default, and its post-quantum AUTHENTICATION has not converged on a name yet. Recheck when a draft is adopted, not before – the implementations are waiting on the same thing. Patrol 2026-10-15: still no pure ML-DSA key type in the 10.5 or 10.6 release notes or in sshkey.c at the 10.6 tag (the only ML-DSA there is the composite mldsa44-ed25519, now enabled by default – see the composite-ml-dsa cell). The key-exchange half this gap contrasts with is now RFC 10042 (August 2026), no longer draft-ietf-sshm-mlkem-hybrid-kex. Examined: IETF datatracker: draft-rpe-ssh-mldsa-03 (individual, standards track), IETF datatracker: draft-sfluhrer-ssh-mldsa-06 (competing individual draft), IETF datatracker: draft-ietf-sshm-mlkem-hybrid-kex-10 (adopted, for contrast; published as RFC 10042, August 2026), OpenSSH release notes 10.6, 10.5, 10.1, 10.0, 9.9, openssh-portable sshkey.c at V_10_6, libssh 0.12.0 release announcement, PuTTY change log and wishlist.
