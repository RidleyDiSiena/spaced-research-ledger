Notes

  • ML-KEM, Primitive: since names the CERTIFICATE rather than a firmware version, because Crypto4A publishes no version for these and the certificate’s issue date is the only dated fact available. The XMSS row says “version not stated” for the same reason and cannot even say that much – it is not on the certificate. Classic McEliece is also supported and is not a register row – one component carrying it is not two, which is the bar for adding one.
  • ML-KEM, FIPS 140-3: Inside QASM Cryptographic Module, Crypto4A Technologies Inc., FIPS 140-3 certificate 5497 issued 2026-08-19. Sunset 2031-08-18.
  • ML-DSA, FIPS 140-3: Inside QASM Cryptographic Module, Crypto4A Technologies Inc., FIPS 140-3 certificate 5497 issued 2026-08-19. Sunset 2031-08-18.
  • SLH-DSA, FIPS 140-3: Inside QASM Cryptographic Module, Crypto4A Technologies Inc., FIPS 140-3 certificate 5497 issued 2026-08-19. Sunset 2031-08-18.
  • LMS / HSS, FIPS 140-3: Inside QASM Cryptographic Module, Crypto4A Technologies Inc., FIPS 140-3 certificate 5497 issued 2026-08-19. Sunset 2031-08-18.
  • LMS / HSS, Firmware signing: THE REASON THE firmware COLUMN EXISTS, and so far the only cell in it. default rather than available because it is not an option a customer enables: the two roots of trust are provisioned at manufacture and the shipping firmware chain carries both signatures. Dual-signing is the conservative choice and the right one – if the hash-based half is ever broken the ECDSA half still holds, and vice versa. Note what this protects that a customer-key cell does not: a module whose customer keys are post-quantum and whose firmware chain is RSA has moved the problem rather than solved it.
  • XMSS / XMSS^MT, FIPS 140-3: Not in any module of this project: the CMVP validated list and the Modules In Process list were scanned on 2026-09-13 and name none carrying it.

Known Unknowns

Cells an engineer would ask about that no cited source has settled yet. not checked means nobody has searched. searching means fewer than 2 passes are done. none found means the search was completed and came back empty, and the artifacts examined are named; a result older than 90 days is marked for recheck.

  • ml-dsa / pkcs11 – searching, 1 of 2 passes: The architecture paper describes what the module does, not which interface reaches it. For a device whose whole pitch is quantum-safe-by-design this is likely well supported, but likely is not a citation. Second pass: the QASM or QxHSM integration guide naming PKCS#11 mechanisms. Examined: Crypto4A, Quantum-Safe by Design (2026-01-08), CMVP certificate 5497.
  • ml-kem / pkcs11 – searching, 1 of 2 passes: As the ML-DSA PKCS#11 gap: the interface question is unanswered by the documents read. Examined: Crypto4A, Quantum-Safe by Design (2026-01-08).
