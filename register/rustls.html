Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • aws-lc-rs – provider, pinned at aws-lc-rs ^1.18 (rustls 0.23.44). Inherits: FIPS 140-3. rustls does no cryptography itself; it takes a provider crate, and aws-lc-rs is the default. It is one of two providers – the other is recorded as the ring edge below rather than left in this sentence, so the page cannot read as though rustls had a single backend. [5]
  • ring, not tracked in this register – provider. Inherits: FIPS 140-3. The other provider crate rustls can be built on, listed beside aws-lc-rs as an optional dependency of rustls 0.23.44. ring is NOT a component in this register, so a rustls built on ring inherits nothing recorded here – and that is a gap in this register’s coverage, not a finding about ring. Recorded as an edge rather than a remark so the count of backends is right and the promotion to a real component is a one-line change if ring is ever tracked. [6]

FIPS 140-3

rustls holds no FIPS 140-3 certificate of its own, and there is no single answer for it: which of its 2 backends this build carries decides, and that is a build-time choice no register can see. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you. What each backend holds:

  • aws-lc-rs (provider, at aws-lc-rs ^1.18 (rustls 0.23.44)) holds no certificate of its own and takes its own cryptography from AWS-LC. See aws-lc-rs.
  • ring (provider) is not a component in this register, so nothing about its FIPS standing is recorded here – and its absence from these pages is not a finding about it.

Notes

  • ML-KEM, TLS 1.3: Hybrid ML-KEM key exchange in the core crate from 0.23.22, toggled by the prefer-post-quantum Cargo feature; earlier only in the experimental rustls-post-quantum crate.
  • X25519MLKEM768, TLS 1.3: Documented as a key exchange group of the aws-lc-rs provider. Merged into the core crate at 0.23.22, having previously lived in the experimental rustls-post-quantum crate; the prefer-post-quantum feature governs preference, not availability.
  • SecP256r1MLKEM768, TLS 1.3: SECP256R1MLKEM768 is a documented group of the same provider.
  • SecP384r1MLKEM1024, TLS 1.3: Absent from the aws-lc-rs provider’s documented key exchange group set, which lists MLKEM768, MLKEM1024, SECP256R1MLKEM768, X25519MLKEM768 and the three classical curves. Recorded as none rather than a gap because that list enumerates what the provider offers.
  • ML-DSA, X.509: ML-DSA certificates enabled by default with the aws-lc-rs provider.
