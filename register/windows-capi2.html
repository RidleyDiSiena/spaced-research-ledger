Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • Windows CNG – platform. Inherits: FIPS 140-3. CAPI2 parses and validates certificates; the signature verification underneath is CNG’s, and so is the FIPS boundary. AD CS states the dependency for the whole Windows PQC surface: “All PQC algorithms require CNG key storage providers.” [3]

FIPS 140-3

Windows CryptoAPI (CAPI2) holds no FIPS 140-3 certificate of its own. It takes its cryptography from Windows CNG (platform), and Windows CNG holds FIPS 140-3 certificate 5313. Whether a given algorithm is inside that validated boundary is Windows CNG’s answer, not this component’s: see the Windows CNG page. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you.

Notes

  • ML-DSA, X.509: Read narrowly, and the narrowness is the point. “Certificate functions” is Microsoft’s own name for this layer, so ML-DSA certificate support is stated rather than inferred – but neither document says whether an ML-DSA chain validates by DEFAULT in every caller, which is what default would claim on this scale. Available is the strongest thing the sources support.

Known Unknowns

Cells an engineer would ask about that no cited source has settled yet. not checked means nobody has searched. searching means fewer than 2 passes are done. none found means the search was completed and came back empty, and the artifacts examined are named; a result older than 90 days is marked for recheck.

  • ml-kem / x509 – searching, 1 of 2 passes: KEM certificates are a different question from signature certificates, and the announcement’s wording does not separate them. AD CS puts ML-KEM issuance in Phase 2, which suggests the validation side is not there either, but suggests is not states. Second pass: the CertEnroll or CryptoAPI reference naming an ML-KEM certificate type. Examined: Microsoft PQC GA announcement, 2025-11-18, AD CS post-quantum overview.
  • composite-ml-dsa / x509 – searching, 1 of 2 passes: AD CS records composite ML-DSA as Phase 2 for issuance; whether CAPI2 can already VALIDATE a composite certificate somebody else issued is unstated, and the two often differ. Second pass: the CryptoAPI chain-building documentation. Examined: AD CS post-quantum overview.
