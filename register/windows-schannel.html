Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • Windows CNG – platform. Inherits: FIPS 140-3. Schannel performs no cryptography of its own; it calls CNG, which is where Windows’ validated modules live. Its FIPS standing is therefore CNG’s, and the pointer says so rather than repeating it. [2]

FIPS 140-3

Schannel holds no FIPS 140-3 certificate of its own. It takes its cryptography from Windows CNG (platform), and Windows CNG holds FIPS 140-3 certificates 5313, 5410, 5408, 4825, 4766, 4687, 4670, 4536, 4515, and has a module in the CMVP queue. Whether a given algorithm is inside that validated boundary is Windows CNG’s answer, not this component’s: see the Windows CNG page. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you.

Notes

  • ML-KEM, TLS 1.3: Roadmapped, not shipped, and deliberately recorded on the KEM row rather than on a named hybrid group: Microsoft names no group, and inventing one would put a claim in the register that its source does not make. The same announcement shipped ML-KEM and ML-DSA in CNG on the same day, so the gap between the two is the finding – the primitives are generally available on Windows while the TLS stack that would use them is still a roadmap item.

Cells an engineer would ask about that no cited source has settled yet. not checked means nobody has searched. searching means fewer than 2 passes are done. none found means the search was completed and came back empty, and the artifacts examined are named; a result older than 90 days is marked for recheck.
