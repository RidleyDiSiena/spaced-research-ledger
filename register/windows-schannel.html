Where the Cryptography Comes From

This component does not implement everything it is asked about. What it inherits, from what, and at which version:

  • Windows CNG – platform. Inherits: FIPS 140-3. Schannel performs no cryptography of its own; it calls CNG, which is where Windows’ validated modules live. Its FIPS standing is therefore CNG’s, and the pointer says so rather than repeating it. [4]

FIPS 140-3

Schannel holds no FIPS 140-3 certificate of its own. It takes its cryptography from Windows CNG (platform), and Windows CNG holds FIPS 140-3 certificate 5313. Whether a given algorithm is inside that validated boundary is Windows CNG’s answer, not this component’s: see the Windows CNG page. Running in an approved mode also needs the validated version on a tested operating environment, which no register can tell you.

Notes

  • ML-KEM, TLS 1.3: CORRECTED 2026-09-13, from planned to available. This component was seeded from Microsoft’s November 2025 announcement, which put TLS in a section headed “What Lies Ahead” – “The development of PQC support for securing TLS is proceeding in alignment with IETF standards” – and that was true when written. It has since shipped: hybrid TLS with ML-KEM groups is GA on Windows 11 and Server 2025, by KB, with X25519MLKEM768 named as the client’s top pick. available and not default because Microsoft says plainly that the groups are not on unless an administrator enables them. THE LESSON IS ABOUT AGE, NOT ERROR: a planned cell is the most perishable thing in this register, and this one was four days old when it went stale. Cells sourced from a roadmap section should be rechecked on a schedule, not when somebody happens to look.
  • X25519MLKEM768, TLS 1.3: THE GROUP, NAMED AT LAST, which is what this gap was waiting for: “the client sends a key_share, pre-generating and attaching the ephemeral public keys for its top pick (X25519MLKEM768) so the handshake can finish in one round trip if the server agrees”, and a worked example shows a negotiated connection reporting TLS 1.3 with the group X25519MLKEM768. So Schannel can now be recorded on the named-group row rather than only on the KEM family. available: Microsoft states the post-quantum groups are not enabled by default and must be set up, using the same mechanisms as existing TLS ECC curves.
